Assessment

Four verified pillars

1

Deterministic Capital Preservation

Fail-closed control architecture

  • Two-tier Kill Switch — a system-wide flag plus a per-agent local check — with three real states and an authenticated manual reset path (core/security.py).
  • Red-teamed, not just asserted safe. The project's own adversarial test found an authentication bypass in the status flag; the fix ships HMAC-SHA256 signing, failing closed on any mismatch.
  • Held under real stress: 451 real trips and 6,618 blocked money-creating calls during one 24-hour live-market run.
  • Fail-soft SMS (Twilio) + Telegram alerting, deliberately decoupled — the control never waits on a notification, and a notification failure never blocks the control.
HMAC-signed 3-state Red-team verified
2

Quantitative Rigor & Governed AI

Closed-form finance theory + constrained ML

  • Marchenko-Pastur random-matrix denoising (Laloux et al. 1999), Almgren-Chriss optimal execution, Extreme Value Theory VaR, Hawkes / Ornstein-Uhlenbeck processes — live-wired into the execution gate, each independently tested.
  • Two independent live ML agents — XGBoost and reinforcement learning — neither able to place an order on its own. A trade fires only once a separate arbitration step confirms both agree on direction; disagreement is a hard veto, not a soft signal.
  • Proven to bind, not rubber-stamp: in one 24-hour live run, the arbitrator vetoed 11,218 conflicting signals against 6,618 approved — it rejected more than it passed.
  • The rarer signal: the same codebase documents techniques evaluated and explicitly declined as non-rigorous — an engineering culture that turns down the dressed-up version of its own pitch.

Compute Infrastructure

Retraining pipeline economics

  • Real, production-grade GPU rental automation (Vast.ai) for low-cost model retraining.
  • Billing-mutating calls fail loud instead of auto-retrying — a deliberate safeguard against silently renting (and paying for) duplicate GPU instances on a transient error.

Institutional Plumbing

Deployment & venue abstraction

  • Enforced Docker network isolation; host networking scoped to exactly the one latency-critical service, with the rationale documented rather than applied everywhere by default.
  • Genuine three-venue execution abstraction — crypto (ccxt), FX (Oanda), and Interactive Brokers — each with disclosed, not hidden, capability limits.
  • Survived a real, uncontrolled multi-hour exchange outage during chaos testing: zero crashes, zero unsafe fills, trading correctly blocked for the full duration.

Beyond the core — research track, not a fifth pillar

Real R&D tooling, deliberately kept behind human review

  • CMA-ES evolutionary hyperparameter search (Hansen & Ostermeier, 2001 — a real, peer-reviewed, decades-old optimization method). Every run produces a proposal in a human-reviewed queue; nothing is applied to a live strategy untouched. The module's own docstring explicitly rejects "the code evolves on its own overnight" as a known overfitting anti-pattern, not a feature.
  • A three-role LLM pipeline (Scout → Hypothesis Generator → Backtest Coder) that reads the project's own real signal stores and proposes new, sandbox-backtested strategy code for human sign-off — never auto-deployed.

Deliberately not claimed here: a spiking neural network ("biological" neuron) module exists in the codebase but is confirmed R&D-only — a manual dashboard trigger, never wired to a live agent. The physics correction in the full memorandum still applies. "Architecture" beyond the infrastructure already covered in Pillar 4 is not a separate, verifiable claim.
